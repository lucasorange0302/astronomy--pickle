## 2026-11-28 새벽 업데이트 (9) — 라이브 센서 고도·상단 파란 선·낮 반투명 땅

### 1) 🧭 지평선 아래로 내렸다 올리면 고도가 틀어지던 문제
- 원인은 **표시 고도와 자세(쿼터니언)의 경계가 서로 달랐던 것**입니다. 화면 표시는 `ALT_MIN(−30°)`에서 잘랐지만 자세 `track.q`는 그 아래로 계속 내려가 `−80°`까지 쌓였고, 보정 목표(`altTarget`)는 `ALT_MIN−4 = −34°`에 묶여 있어 **폰을 아래로 향한 채 1~2초만 있어도 보정이 자세를 위로 30~45° 끌어올렸습니다.** 그 상태에서 폰을 올리면 표시 고도가 실제 방향과 어긋난 채 천천히(약 33°/s) 따라붙었습니다.
- 수정: ① 화면 표시와 자세의 경계를 **같은 `ALT_MIN·ALT_MAX`로 통일**하고, ② `track.alt`가 아니라 **자이로 적분이 끝난 자세 `track.q`의 고도를 매 프레임 경계에 고정**(`setCamAlt`)합니다. 기기가 범위 밖을 보는 동안에는 넘어간 만큼의 회전이 자세에 쌓이지 않으므로, **경계를 다시 지나는 순간부터 1:1로 따라옵니다.** ③ 보정 목표도 `clamp(rawAlt, ALT_MIN, ALT_MAX)`로 잘라 경계에서 보정과 자이로가 서로 당기지 않게 했습니다.
- 검증(수치): `app.js`의 자세 파이프라인을 그대로 옮긴 시뮬레이션에서 **−70°를 2.5초 머문 뒤 복귀** 시, 수정 전에는 폰이 −24.8°일 때 표시가 −2.1°(22° 틀어짐)였고 지평선으로 돌아와도 2° 안에 들지 못했지만, 수정 후에는 표시 −26.7°로 2° 안, 복귀 후 **0.05초**에 정확히 일치했습니다. 방위 0°·90°·180°·270° 네 방향 모두 같습니다.

### 2) ➖ 상단 칩 아래 파란 가로선 제거
- 정체는 **지평선 고리를 그리던 선이 화면을 가로지른 자국**이었습니다. `hzPts`를 만들 때 시선 뒤쪽(`den < 0.12`)이라 `project()`가 `null`을 준 점을 **그냥 버려서**, 잘려 나간 양 끝(화면 밖 멀리, 같은 높이)이 **직선으로 이어져** 화면 위쪽을 가로지르는 얇은 파란 선이 됐습니다(색이 `pal.horizon`과 같은 이유).
- 수정: `null`을 그대로 `strokePts`에 넘겨 그 자리에서 선을 끊습니다. 시야 70°·고도 2°·방위 215°에서 화면 y≈91px에 그어지던 선이 사라지고, 고도 0~10°의 여러 방위에서 **가로지르는 가짜 선분 0개**를 확인했습니다. 실제 고도 0° 지평선과 방위선은 그대로입니다.

### 3) 🌤 낮에도 지평선 아래가 은은하게 비침

## 2026-11-27 밤 업데이트 (8) — 라이브 투명도·원근·핀치확대·뉴스번역·격자

### 1) 🌍 라이브 하늘 — 지평선 아래 반투명 땅
- 지평선 아래 천체가 보이지 않던 두 가지 원인을 고쳤습니다. 별을 `alt < −2°`에서 자르던 조건을 **−45°**까지 넓히고, 땅(`ground`) 채우기를 거의 불투명(`rgba(3,6,14,.92)`)에서 **반투명**(`rgba(3,6,14,.55)` → 아래로 갈수록 `.88`로 짙어지는 세로 그라데이션, 레드라이트는 `rgba(26,4,2,.55)`)로 낮췄습니다.
- 그리는 순서를 바꿨습니다: 하늘·별·별자리·딥스카이·행성·달·태양을 **먼저** 다 그린 뒤, 땅을 반투명하게 덮습니다. 그래서 지평선 아래의 별과 별자리 선이 땅 너머로 은은하게 비치고, **지평선 경계선(2px, 불투명도 .8)과 동·서·남·북 방위 표시**는 그 위에 또렷하게 그어집니다.
- 땅의 경계는 화면 **행마다 지평선(고도 0°)과 만나는 x 를 2차식으로 정확히 풀어** 계산합니다(입체 투영의 역변환 `dx=2u/(1+t)`, `dy=(1−t)/(1+t)`, `dz=2w/(1+t)`). 그래서 지평선이 곡선이 되어도, 위를 보아 한 행이 지평선을 두 번 지나는 경우에도 세로 띠 같은 얼룩이 생기지 않습니다.
- 터치 판정도 그대로입니다: 화면에 그려진 별은 지평선 위·아래 모두 `live.hits`에 들어가 눌러서 정보를 볼 수 있습니다(정보 창의 '지금 고도'가 −값으로 나옵니다).

### 2) 🥽 라이브 하늘 — 구면(입체) 투영이 기본
- 예전에는 `fov > 85°`일 때만 입체 투영, 기본 60~70°에서는 평면(gnomonic)이라 지평선이 항상 일직선이었습니다. 이제 **모든 시야에서 입체(stereographic) 투영**을 씁니다. 화면 거리 = `tan(θ/2)`이라 시야 가장자리 왜곡이 완만하고, 위아래로 기울이거나 줌 아웃하면 **지평선이 완만한 곡선으로 휘어** 하늘 돔·지구의 둥근 느낌이 살아납니다. 시야 절반이 화면 가장자리에 정확히 오도록 배율을 잡아, 고도 30°·60° 고리와 방위선도 끊김 없이 매끄럽게 이어집니다.
- 시선 뒤(θ≳152°)는 값이 무한대로 발산하므로 그리지 않습니다(선은 자연스럽게 끊깁니다).

### 3) 🤏 두 손가락 핀치 확대·축소
- **라이브 하늘**: 두 손가락 거리로 시야(화각)를 **15°~115°**에서 부드럽게 조절합니다. 벌리면 확대, 오므리면 축소이며, 핀치 중에는 한 손가락 드래그 회전을 멈추고, 핀치가 끝나면 화각이 그대로 유지됩니다(슬라이더 값도 함께 갱신). 핀치 뒤의 손가락 뗌은 '탭'으로 보지 않아 엉뚱한 정보 창이 열리지 않습니다.
- **전천 지도**: 두 손가락으로 **1×~3.5×** 확대·축소하고, 확대한 상태에서는 한 손가락으로 이동합니다. 확대는 손가락 사이 지점을 중심으로 이루어지고, 지도 밖으로 나가지 않게 이동 범위를 제한합니다. 오른쪽 위 **「2.4× · 원래대로」** 버튼으로 1× 복귀. 확대 상태에서도 별·행성·달을 누르면 그 천체 정보가 열립니다(화면 좌표 변환은 `getBoundingClientRect` 기준이라 배율과 무관하게 정확). 모바일 브라우저의 페이지 확대와 충돌하지 않도록 `touch-action`(1× `pan-y` / 확대 `none`)과 iOS `gesturestart` 차단을 넣었습니다. 데스크톱에서는 트랙패드 핀치(ctrl+휠)도 같은 확대·축소로 동작합니다.

## 2026-11-27 밤 업데이트 (7) — 오늘 밤 화면 「지금」 시각이 칸에 보이게

### 🕒 「지금」을 눌러도 시각 칸이 비어 보이던 문제
- 원인: `지금` 버튼(`#btnNow`)과 첫 진입이 `state.timeStr = ''`로 두고 `#timeInput.value = ''`까지 비웠습니다. 아이폰 사파리는 값이 빈 `<input type="time">`을 `--:-- --`(또는 빈 칸)로만 그려서, **시각을 되돌린 것이 아니라 시각이 사라진 것처럼** 보였습니다. 화면 위 요약도 `11월 27일 (금) 지금`처럼 시각 없이 표시됐습니다.
- 수정: 시각 칸에는 늘 **실제로 계산에 쓰이는 시각(HH:MM)**을 채웁니다(`timeFieldValue()`). 상태의 뜻은 그대로입니다 — `state.timeStr === ''`·`state.simJd == null`이면 오늘은 지금 추적, 다른 날짜는 22:00, 타임랩스·하늘 시각 카드는 그 시각.
- `지금` 추적 중에는 5초마다 시계를 확인해 **분이 바뀌면 시각 칸·요약·하늘을 같은 시각으로 다시 그립니다**(`tickLiveClock`). 직접 시각을 고르면(`state.timeStr` 채움) 그 시각으로 고정되고 자동 갱신이 멈춥니다. 탭으로 돌아오면(`visibilitychange`) 바로 한 번 맞춥니다.

- 표시 보강: 요약은 `11월 27일 (금) 23:09 (지금)`, 전천 지도 쪽은 `23:09 KST (지금)`. `지금` 버튼은 추적 중일 때 눌린 모양(`aria-pressed="true"`, 금색 테두리)으로 보입니다. `nowClockStr()`은 시계에서 바로 읽어 23:59:30이 `00:00`으로 반올림돼 보이던 30초 틈도 없앴습니다.
- 칸 모양 점검: `styles.css`·`layout-mobile.css`에 시각 칸 글자를 숨기거나 자르는 규칙은 없었습니다(색 `rgb(238,242,251)`·불투명·`text-indent:0`). 320px 폭에서도 칸 129px·글자 32px로 잘리지 않고 `지금` 버튼도 칸 안에 들어옵니다.

- 모바일 390px에서 두 셀렉트가 카드 밖으로 나가지 않도록 `min-width: 0; max-width: 100%`를 적용했고, 실측 넘침은 0px입니다.

### 2) 사진 갤러리 — 천체마다 5~8장
- `gallery.js` 하나를 **도감 상세 모달 · 하늘 전체 도감(메시에/NGC) 모달 · 라이브 하늘 정보 시트**가 함께 씁니다.
- 사진 순서: ① `assets/space/` 로컬 사진(photo-sets.js의 천체별 여러 장 + catalog-photos.js 대표 사진) → ② **NASA Image and Video Library**(`images-api.nasa.gov`, CORS 허용)에서 이름·번호로 검색한 관련 사진 → ③ **NASA SkyView** 실제 하늘 탐사 사진(DSS2 적색·청색·적외선, 2MASS-K, WISE 3.4, ROSAT X선).
- 실제로 로드된 사진(`naturalWidth > 0`)만 세고, 중복 URL·깨진 URL은 버립니다. 모두 실패하면 성도 SVG로 대체합니다.
- 1/6 카운터 · 썸네일 · 좌우 화살표 · 손가락 스와이프 · 키보드 ←/→ 를 지원하고, 30분 동안 결과를 캐시합니다.
- **사진 신뢰성 규칙(2026-11-27 보강)** — 실사진만 나오게 아래를 강제합니다.
  - **항성은 NASA 텍스트 검색을 아예 쓰지 않습니다.** `type` 이 비어 있는 라이브 하늘 객체(kind: star)까지 잡도록 이름·Bayer 명칭(α Lyrae)·별 목록(`SKY_DATA.stars`, `catalog-photos.js` 의 `star: true`)으로 판별합니다. 'Vega' 검색이 라스베가스(Vegas)·록히드 베가·베가 로켓을, 'Sirius' 가 위성을, 'Orion' 이 오리온 우주선을 물어 오던 문제 때문입니다.
  - **NASA 결과는 제목+설명+키워드를 모두 검사**합니다. `las vegas`, `artist concept`, `illustration`, `concept`, `artwork`, `diagram`, `chart`, `infographic`, `poster`, `rocket`, `launch`, `spacecraft`, `astronaut`, `crew`, `logo`, `banner`, `rendering`, `simulation`, 도시·미국 지명 등이 하나라도 있으면 버립니다.
  - 천문 근거 단어가 없거나, 천체 이름이 **단어 단위**로 제목(또는 키워드+번호)에 확인되지 않으면 채택하지 않습니다. 본문에 다른 메시에/NGC 번호가 적힌 항목(예: 'Southern Ring Nebula'=NGC 3132)도 제외합니다.
  - 망원경·관측소 촬영 근거(Hubble·Webb·Spitzer·Chandra·ESO·observatory 등)가 있는 항목을 앞에 놓습니다.
  - 2MASS-K 는 기본 스케일에서 새까맣게 나와 빈 사진처럼 보이므로 `Scaling=HistEq` 로 밝기를 폅니다. SkyView 는 한 번 실패 시 한 번 재시도하고, 행성상성운(M57·M27)이 태양계로 오인돼 SkyView 가 빠지던 버그도 고쳤습니다.

### 3) 모바일 상단 바 제거
- `mobile.html` / `layout-mobile.css`에서 상단 헤더를 접어(높이 0) 화면 전체를 콘텐츠와 라이브 하늘에 씁니다. 탐색은 하단 5탭 바가 담당합니다.
- 헤더에 있던 **레드라이트 모드 · 플랜 공유 · 글자 크기**는 하단 **☰ 더보기** 메뉴 안 "화면 · 공유" 그룹으로 옮겼습니다. 더보기 메뉴는 하단 탭 바 위에 시트처럼 뜹니다.
- 라이브 하늘 뷰 높이를 `100dvh − 하단 탭 바`로 다시 계산해 세로 화면을 꽉 채웁니다. 데스크톱판은 그대로입니다(헤더 63px 유지).

### 4) 강수량 — 시간별 구름양 차트와 관측 지수
- Open-Meteo 호출에 `precipitation`(강수량 mm)을 추가해 `cloud_cover, precipitation, precipitation_probability`를 한 번에 받습니다.
- 차트의 각 시간 칸에 **강수량을 파란 막대**로 겹쳐 그렸고, 비·눈이 오는 칸은 💧 표시와 함께 시간 라벨 색이 바뀝니다. 툴팁에는 `22시 · 구름 85% · 강수확률 90% · 강수량 2.1mm`처럼 모두 나옵니다.
- 차트 아래 **☔ 비·눈 예보** 줄에 시간별 강수량·확률을, 패널 하단에 밤 평균 구름·평균 강수확률·밤 합계 강수량을 적었습니다.
- 관측 지수는 한 시간 최고 강수량(`mmMax`)과 평균 강수확률로 추가 감점합니다(강수확률 30%부터, 강수량 0.2mm부터). 예: 같은 조건에서 비 없음 44점 → 3.4mm/시·95% 8점.
- 공유 텍스트와 요약 카드 배지에도 강수 정보가 들어갑니다.
